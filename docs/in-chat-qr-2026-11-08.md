# Small in-chat QR transport — 8 November 2026

## Decision and result

The user approved a small QR tile in the top-right corner of the existing Lua chat, explicitly relaxing the earlier requirement for fully invisible transport. Enter must still be the only send action. No separate transfer window, hexadecimal text, packet headers or diagnostic markers should appear during the chat.

**The Mac laboratory now delivers real AI answers through this flow during an uninterrupted game session.** Three questions completed, including observed quest progress and a Swedish question/answer. This is evidence to continue, not a claim of release readiness or Windows compatibility.

## Player flow

1. Write a question and optionally include current character context.
2. Press Enter. The draft remains available while a single request is pending.
3. The QR tile appears inside the chat. The existing status reports waiting/thinking/receiving. Input is locked against a second concurrent request.
4. The reader validates the same request twice, registers/identifies the character locally, and submits the text and approved context through the existing Go companion and backend to Berget.
5. The existing reusable file-presence return channel carries the answer back into Lua. Its block receipts also use the QR tile; there is no separate receipt-text window.
6. The answer appears in the chat and the tile disappears after completion. A subsequent question reuses the same location and return files.

The tile does not animate, fade, rotate or pulse: a stable, high-contrast image is required for decoding. It changes only when the protocol has new information to send. This static treatment also avoids a separate motion/reduced-motion dependency.

The chat reserves a column so messages remain readable rather than passing under the QR. The reservation follows resize and movement. The prototype targets approximately 110 UI units but rounds modules to integral physical pixels; at this client's effective UI scale the full request tile was roughly 125 units across. Receipts have fewer modules and are smaller. This is not yet a minimum-size study across displays, UI scales or graphics settings.

## Implementation

- `apps/addon/Jornia/QR.lua`: first-party QR Model 2 byte encoder, UTF-8 ECI 26, versions **4-L** and **16-L**, fixed valid mask 0, Reed–Solomon parity and standard four-module quiet zone. No third-party QR implementation or finished companion framework was copied or added.
- `QRTransport.lua`: optional display adapter for the existing transport, drawing horizontal black runs with pooled Lua textures. It hides the legacy card's text, corner markers and chrome and reparents the frame into the chat. Its existing update loop remains active.
- `Transport.lua`: optional display hook; failed rendering must reject acceptance and preserve the draft rather than strand a hidden pending operation. The legacy OCR adapter remains available.
- `scripts/experiments/ocr/capture.m --qr`: Apple's barcode decoder, not natural-language text OCR. QR results are restricted to Jornia request/receipt formats.
- `scripts/companion/reader.py --qr`: exact QR payload parsing, two consistent observations, duplicate-request suppression, existing local mutation receipts and the existing checked return bus.

A request QR contains `JORNIAQR1`, request ID, character binding, nonce, Adler-32 and raw UTF-8 JSON. The receiver reconstructs the existing version-4 envelope and applies its schema, identity, integrity and size checks. QR does not require OCR glyph substitutions or candidate repair. Receipts retain sequence/nonce/binding/prefix-check validation. These checks detect accidental corruption and stale/mismatched frames; they are not cryptographic authentication of arbitrary screen content.

The encoder accepts at most **584 UTF-8 bytes** including the QR header. The display permits at most **523 body bytes**. The normal context packer still targets **480 body bytes** and questions remain limited to **160 UTF-8 bytes**. It prioritizes the named/selected quest and may remove other quests, gear/professions and narrative; truncation is explicit. A small QR is **not** an unlimited full-journal transport. More context would require measured larger symbols, a different compact representation or an acknowledged multipart protocol.

### Capture boundary

The helper uses the existing **WoW-window-only** ScreenCaptureKit stream. Initially, and after losing the tile, it searches that window locally for a Jornia QR. Once located, barcode decoding uses a crop around the tile; five misses trigger reacquisition. The successful targeted samples below used a **187 × 187 capture-pixel crop**.

**This does not yet configure ScreenCaptureKit itself to capture only the Lua window.** Full WoW-window pixels briefly exist in local process memory before cropping. Other applications are not captured; normal reader operation saves neither screenshots nor QR contents to logs and sends no images to the server. Only validated text and approved context are submitted. A strict region-only capture implementation remains a separate improvement; do not describe the current implementation as capturing only the chat at the OS boundary.

The existing Mac game process stayed running throughout. No reload, logout, shutdown, memory reading, injection, gameplay movement or combat automation was used. Laboratory code was activated through installed, unused load-on-demand slots. Screenshots were inspected to confirm the visible answers and pending/error states.

### Failure and recovery observations

- Replacing the display adapter in the live lab initially left old QR textures behind. The next code could not be read and no new request was registered by the reader. This was a failed experiment, not an AI success. Initialization now hides old regions and refuses replacement while an operation is pending. A fresh transport instance restored drawing without reloading the game.
- The draft survived that failure. An explicit retry succeeded with the correct Swedish answer.
- Stopping the reader after a completed response made the next send show “Start the local Jornia reader and wait a moment.” The draft and context choice remained, and there was no new accepted request.
- Restarting the reader did not send the draft automatically. An explicit Enter then delivered one answer. No extra acceptance appeared while a request/receipt remained visible across repeated captures.
- Hard crashes during every return phase, UI close/reopen during delivery, movement during the active transfer, combat, minimized/occluded game windows and long sessions are **not yet validated**. Movement/resize was tested between requests.

## Local setup and remaining work

The current Mac installation has the QR files and TOC entries, with a backup of the previous addon. It is already active in the current session. These instructions are for a prepared development environment, **not a public installer**:

```sh
python3 scripts/install_companion_ui.py --root '/path/to/World of Warcraft/_forever_' --qr

clang -fobjc-arc scripts/experiments/ocr/capture.m \
  -framework Foundation -framework AppKit -framework Vision \
  -framework CoreGraphics -framework ScreenCaptureKit -framework CoreImage \
  -framework CoreMedia -framework CoreVideo \
  -o .cache/ocr-test/jornia-qr-capture

python3 scripts/companion/reader.py --qr \
  --root '/path/to/World of Warcraft/_forever_' \
  --capture .cache/ocr-test/jornia-qr-capture
```

Only one reader may own the return files. Stop the old reader gracefully before changing modes; retain the existing recovery procedure for interrupted owned files. Installing files does not activate them inside an already running client. Use an available, syntax-checked lab slot for live experiments; **do not substitute a reload or restart without new explicit permission**.

## Format/platform references

The QR parameters follow the [ISO/IEC 18004 symbology specification](https://www.iso.org/standard/83389.html); [DENSO WAVE explains versions and capacity](https://www.qrcode.com/en/about/version.html). Decoding uses Apple's [VNDetectBarcodesRequest](https://developer.apple.com/documentation/vision/vndetectbarcodesrequest) and [payloadStringValue](https://developer.apple.com/documentation/vision/vnbarcodeobservation/payloadstringvalue). Existing outbound visual transport and reusable return mechanisms remain subject to the attribution and limits in the prior-work audit; this experiment makes no new invention claim.
